## Points à ne pas défaire

### Données, dates, sauvegardes, RGPD

- **Aucune donnée d'usager dans un repo public**, même temporairement. Sauvegardes vers le repo privé `GH_REPO='maswaddpt47-cmyk/sms-mail-multi-backups'` ; rétention 30 jours (`GH_BACKUP_RETENTION_JOURS`), `ghCleanOldBackups()` garde toujours la plus récente. Jeton GitHub : champ en formulaire de connexion reconnu par Proton Pass (13/11, clé `ess-gh-token` inchangée) ; un effacement des données du navigateur efface le jeton, Proton Pass sert à le remettre.
- **Cloisonnement par profil** : toute donnée d'usager passe par `ess-<profil>-…` (`pk`/`pkFor`) ; une migration ou un archivage ne touche aucune clé d'un autre profil. **Migrations localStorage** : une migration non testée a déjà réduit 11 CMS à 6 ; toute migration délicate mérite un test ciblé avant commit.
- **Rétention RGPD** (`archiveYear`) : supprime le détail nominatif d'une année révolue après agrégation anonymisée — irréversible, confirmation obligatoire. **Archives `ag017-v1`** (AG-017) : purge par cohorte (`entryYear`), contributions rangées à leur date, fiches déjà comptées (`idsFiches`) et non réconciliées (marqueur `nonReconciliee`, jamais retiré) exclues des sommes, recomptage indépendant (`recompterCohorte`) et invariants avant toute purge, lecture stricte (`archiveAg017Complete`), export de contrôle sans identifiant ni libellé, anciennes archives lues à l'identique. Archives déjà calculées **jamais recalculées** (elles gardent l'ancien comptage par fiche et le lun.–ven. de `businessDaysBetween`). Tests : `check-archives.js`.
- **Dates et `ts`** (AG-016) : la date du jour est `jourParis()` (jamais `toISOString().slice(0,10)` ni l'heure de l'appareil) ; tout lecteur de `ts` passe par `lireTs`/`afficherTs` ; les nouvelles fiches écrivent `ts` par `tsParis()` (ISO avec le décalage de Paris, pas `Z`) ; le `ts` des mandats reste en texte français ; anciens `ts` jamais réécrits. **`id`** : donné aux seules nouvelles fiches (`nouvelIdFiche`), jamais écrasé ; localisateurs : repli vers une unique fiche ancienne sans `id`, jamais une autre fiche identifiée. Tests : `check-stats-rdv.js`, `check-ecritures.js`.
- **Sens des champs de date** (vérifié dans le code le 01/11) : `dateReception` = réception de la demande (facultatif, repris de `o.date` quand le message est préparé depuis Orientations) ; `dateDemande` = date du message (aujourd'hui par défaut), pas une réception ; `premierePreparationAt` = première préparation (depuis le 22/10 seulement) ; `date` = date du RDV ; orientations : `o.date` = date de la demande d'orientation, `o.commune` = structure, `o.motif` libre, `o.done` = traitée (sans date), non archivées.
- **Réception de la demande** (AG-022, AG-023) : une ancienne `dateDemande` reprise n'est jamais affichée ni préremplie comme réception ; seule une confirmation explicite (bouton ou date saisie) l'enregistre ; un formulaire ne réécrit `dateReception` que si le champ a changé (`sourceReception`, `receptionAEcrire`, R1/R2/NR1) ; `receptionDateFor` reste le seul lecteur de la préparation moyenne. **Avant le 22/10** : `dateDemande` ≤ 2026-10-22 sans `dateReception` = réception saisie dans l'ancien champ (état `ancienne`), comptée, jamais remise « à confirmer », borne non étendue. Tests : `check-ecritures.js`, `check-reception.js`, `check-delai-attente.js`.
- **Fiche sans message** (D1) : `body:''` explicite (import ICS, planning) = pas un dossier ni une mesure de réactivité, comptée à part ; une fiche sans champ `body` reste comptée.
- **Lien orientation → dossier** (AG-033, 16/11/2026, amendé par Codex) : `orientationId` (texte, `o.id`) écrit sur la fiche à l'enregistrement du dossier (Générer **et** copie, source figée au départ), seulement si nom et prénom sont encore ceux de l'orientation (`orientationALier`) ; `done` écrit dans la **même opération** que la fiche (`addHistory(item, prepared, lienOrient)`, clé orientations dans le retour arrière), jamais à part ; à la fusion, un lien existant n'est jamais remplacé (lien différent → orientation non marquée, avertissement) ; « Traitée » = dossier préparé, pas envoyé ni réalisé ; anciennes fiches jamais réécrites ; export CSV inchangé (le distinguer = nouveau bloc). Carte d'orientation : première fiche liée de l'historique hors indisponibilité (`ficheDeOrientation`). `restaurerCles` ne réécrit pas une clé encore à l'état d'avant. Tests : `check-ecritures.js` (parcours réels), `check-orientation-lien.js`.
- **Écritures sûres** (AG-013, étape 2) : une fiche, l'ouverture de sa journée, la pause déjeuner et le compteur d'export sont enregistrés ensemble ou pas du tout (`operationHistorique`) ; `addHistory` renvoie true seulement si tout est enregistré et le message suit son résultat. Rappel d'export « N messages non sauvegardés » toutes les 5 fiches, seulement sans jeton ou si `gh-last-backup` > 24 h ; `since-export` retombe à 0 après export JSON ou sauvegarde GitHub. Test : `check-ecritures.js`.
- **Sauvegarde et calendrier** (AG-032) : une sauvegarde sans `calendarIcs` ne touche jamais au calendrier ; une sauvegarde avec le champ le remplace ; vide écrit en clair ; champ invalide → import refusé ; sauvegarde auto avec envoi différé ; restauration GitHub > 1 Mo en raw. Non mesuré : envoi réel de plusieurs Mo.
- **Doublons de fiche** (23/09, 05/10) de cause non identifiée : `addHistory` dédoublonne par date + heure + CMS (`cmsKey`) + nom + prénom ; une 3ᵉ occurrence passe le critère AGORA 3. **Statut « Réalisé » revenu à « Confirmé »** (01/11, hypothèse non vérifiée : restauration GitHub d'une sauvegarde plus ancienne d'un autre appareil) : à rouvrir si le cas se reproduit, avec l'appareil et la restauration en cause.
- **Rappel de la veille : gardé, non utilisé** (01/11) : un rappel automatique part d'une autre application ; « ✓ Envoyé » (`h.rappelVeille`) n'est pas tenu à jour. Ne pas s'en servir comme donnée, ne pas retirer la fonction.
- **Captures et fichiers envoyés à Claude** : jamais de données réelles (charte IA CD47 §4) ; Claude ne lit jamais les sauvegardes réelles (règle 59) : diagnostic calculé dans le navigateur de l'utilisateur, nombres seuls à l'écran.
